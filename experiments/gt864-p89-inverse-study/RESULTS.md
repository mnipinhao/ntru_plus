# P89 — NTRU+864's inverse: the lane basis does not port, and what does

Roadmap item 2 said to close 864's +140 ns inverse gap by porting the
(component, half) lane basis that P64-P71 gave 1152.  It does not port.  The
prize is real and sits somewhere else.

## The gap, measured directly

`poly_invntt_ternary` against Official's `poly_invntt_scale`, gated harness, M2:

```
  GT poly_invntt_ternary               419.4 ns
  Official poly_invntt_scale (+ copy)  276.2 ns
```

+143 ns, which confirms P84's profile attribution of +140.

## Why the lane basis does not port

The two trees run the *same arithmetic*.  Counting the two invntt16 leaves:

| | 864 | 1152 |
|---|---:|---:|
| `sqrdmulh` / `mls` / `mul` / `sub` / `ext` / `ldr` / `add` | 101/101/98/64/64/172/128 | **identical** |
| `umov` + `strh` | **224 + 224** | 0 |
| `str` | 0 | 64 |

Every arithmetic instruction is the same.  The entire difference is the output
path, and at the KEM level it is **1,728 of the inverse's 6,784 dynamic
instructions, 25%**, spent extracting lanes through general-purpose registers
and storing two bytes at a time.

`generate_main.py` swapped 1152's inner four lanes from four *s* values to four
*components*, which made each output group four consecutive halfwords and
collapsed 4 UMOV + 4 STRH into one STR D.  Running its structural assertions
against 864 with `STRIDE=27, DEG=3` **passes**: 32 `ext` at #8, all self-rotates;
all 128 UMOV/STRH pairs satisfy `r % 3 == 0 and r // 3 == lane`; 32 groups, each
from one register.  The machinery fits.

The arithmetic is what does not.  A call at 864 covers one component across four
*s* values, and six calls cover three components times two *s* blocks.  Swap the
inner lanes to components and a call covers one *s* value across three
components -- three lanes of four, and **eight calls instead of six**.  The
33% extra calls cost more than the stores save.

1152 does not have that problem because it has four components and four inner
lanes: the swap is exact and nothing is wasted.  **This is the same obstacle the
serializer hit in P87** -- 864's degree-3 leaves give six-byte units where
1152's degree-4 give eight -- and it has now blocked two ports.

## What is available

Store shapes, extracted from the scheduled code:

* **`inverse16_tail.S`**: lanes 0, 1, 2 of a register go to **three consecutive
  halfwords** -- 432, 433, 434 and so on.  It is already in the component basis.
  `str s` covers lanes 0 and 1 at an immediate offset; lane 2 still needs a
  UMOV/STRH pair, so three instructions replace six.  About -96 per tail call.
* **`inverse16.S`**: lanes 0..3 go to 27k + 3l -- stride three halfwords, never
  adjacent, because a group's three components are written by three *different*
  calls.  No immediate-offset store covers it.  `st1 {v.h}[l], [xT], #6`
  post-indexed walks the four in one instruction each, one `add` per group, so
  five instructions replace eight.  About -96 per main call.

Together roughly **-704 dynamic instructions, -10%**, which scales to about
**376 ns from 419** -- 43 ns of the 143.

That is worth having but it is not the item as written, and it carries a real
risk the counting does not show: both files are Slothy-scheduled, and a
post-indexed address register serialises stores the scheduler had interleaved.
The tail is the safer half and has no such chain if `str s` is used with an
immediate.

## A correction

P85 recorded that roadmap item 1 was partly blocked because "the file is
generated by a `generate_ntt9.py` that is not on this machine".  That is wrong.
**Every generator is on disk**, under `experiments/`:

```
  generate_i9.py       experiments/gt1152-p68-i9-lane-basis/
  generate_main.py     experiments/gt1152-p67-main-lane-basis/
  generate_tail.py     experiments/gt1152-p22-tail-asm/
  generate_kernels.py  experiments/gt1152-p07-inverse/
  generate_ntt9.py     experiments/gt1152-p04-forward-8bank/
  generate_pairs.py    experiments/gt1152-p18-codec-registers/
```

The earlier search used `find -name A -o -name B` and truncated the result with
`head -20`, which cut the `experiments/` hits.  Item 1's other obstacle -- that
`ntt9.S` never holds the right vectors together, so the change is to the bank
schedule and not to store addressing -- still stands, and that was always the
binding one.
