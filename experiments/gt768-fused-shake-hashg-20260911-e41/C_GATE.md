# C: fixed-size hash_g wrapper

Experiment: gt768-fused-shake-hashg-20260911-e41.
Baseline A: a64e7035cb13410554af1c67870d4132a30037b4.
Previous candidate B: 5300d169fa04b2459bf1093c435e9e22843cfee4.

Observation: B saves roughly 174 hash_g cycles but adds 3968 .text bytes to
the full KEM. Its generic absorber/squeeze logic retains two scratch buffers,
variable-length branches and compiler-generated byte shuffles.

Category: memory access and code size, jointly changed by fixed-size
specialization.

Hypothesis: a 1152-byte input / 192-byte output wrapper can directly absorb
eight full blocks and a known padded tail, then directly serialize 17+7
output lanes, while keeping the existing ten permutation calls. It should
reduce B's cycles and linked code size.

Exact change: replace the experimental generic prefix helper with
ntruplus_hash_g_fixed. Prefix is always 1. Fixed byte counts permit direct
tail XOR and exact-size output copies. Use alignment-safe memcpy for
little-endian 64-bit inputs, with the existing portable load64 fallback on
other endianness; no changes to the generic SHAKE functions.

This is a composite C gate (fixed sizes, eliminated scratch, direct word
load expression). A/B/C timing does not separately attribute each factor.

Expected static effect: no generic length division/remainder; no 200-byte
tail scratch or 136-byte squeeze scratch; fewer shuffle instructions.
One 200-byte state clear remains. Removed buffers never exist, so eliminating
their clears preserves the policy of clearing materialized SHAKE state.

Register pressure: compiler-managed C locals, same external scalar
permutation ABI; no cross-permutation register-resident state.

Correctness: unchanged domain and SHAKE padding, ten permutations, exact
192-byte output, input fully consumed before output (including overlaps).
Targeted tests audit clear content/count and permutation count, all eight
input alignments, input-tail guard pages, output canaries and overlaps.
Full package KAT/ABI/canonical/failure/cleanup checks precede timing.

Falsifier: any contract mismatch, failure to shrink full-KEM text relative
to B, or no reproducible cycle improvement on Pi5. Retain A/B as measured
controls. Production promotion is outside this gate.

## Result: accept C as the next experimental champion

Date: 2026-09-12. Production remains at
a64e7035cb13410554af1c67870d4132a30037b4; the tracked SUPERCOP leaf is unchanged.
The generic B helper is removed from the candidate package rather than kept
as dead source. B remains reproducible from its recorded commit, including
its dedicated test_prefix.c test and the runner's default B mode.

### Measured cycles

Same-batch A/B/C, Pi5 Cortex-A76 core 3, GCC 14.2.0, -O3
-march=armv8-a -mtune=cortex-a76 -fomit-frame-pointer
-ffunction-sections -fdata-sections -std=c99.

66 groups, 2000 operations/sample, 100 warmups. The six ABC permutations are
each used eleven times. All output sinks match. C beats both A and B in every
group for every operation.

| Operation | A p50 | B p50 | C p50 | C vs B | C vs A |
|---|---:|---:|---:|---:|---:|
| hash_g | 10693.5 | 10522 | 9476 | -9.94% | -11.39% |
| Encap | 31937 | 31754 | 30720 | -3.26% | -3.81% |
| Decap | 29053 | 28914 | 27859.5 | -3.65% | -4.11% |

Median paired savings against B: 1045, 1037 and 1058.5 cycles.
Paired p10/p90 savings: 1037/1054, 1020/1074 and 1040/1079.
This is an experimental comparison against the scalar-Keccak GT champion,
not a new Official SUPERCOP benchmark.

Throttling remains 0x0. Pre/post timing temperatures are both 64.2 C and
pre/post timing clocks are approximately 2.4 GHz. The idle clock before
builds was 1.8 GHz. These are boundary samples, not continuous monitoring.

### Linked size and implementation

| Item, bytes | A | B | C |
|---|---:|---:|---:|
| full Encap binary .text | 73328 | 77296 | 73744 |
| prefix/fixed helper | n/a | 4016 | 464 |
| own stack frames at permutation | 2112 | 688 | 400 |
| materialized SHAKE buffers cleared per hash_g | 1689 | 536 | 200 |

C shrinks full KEM .text by 3552 bytes relative to B; it is only 416 bytes
larger than A. Its own stack consists of a 272-byte C frame and the unchanged
128-byte permutation frame, excluding higher callers and libc frames.
This is static frame accounting, not a runtime whole-process stack maximum.

The linked scalar permutation has exactly the same 288 instruction words
(1152 bytes) in A/B/C. The C wrapper has no uzp/zip/trn/tbl/tbx instructions.
GCC emits direct unaligned scalar/vector loads and vector XOR for the full
blocks. There is one first-block call, seven loop calls, one padded-tail
call and one second-squeeze call. State is still stored in memory at each
permutation boundary.

### PMU

Six long runs per variant, all six ABC orders, 200000 calls/run. User-space
events report 100% scheduled time. Startup overhead is amortized, and
ld_spec/st_spec are speculative events rather than retired memory counts.

| Per hash_g, median | B | C | Reduction |
|---|---:|---:|---:|
| instructions retired | 30321.1 | 28092.1 | 2229.0 |
| ld_spec | 1349.8 | 1248.7 | 101.1 |
| st_spec | 799.7 | 759.0 | 40.7 |
| stall_backend | 1001.7 | 543.8 | 457.9 |

The result supports the combined specialization. This gate does not isolate
the cycle contributions of scratch removal, word-load expression and fixed
control. It does establish that reducing ten permutation calls is unnecessary
to obtain the measured extra approximately 1000 cycles.

### Correctness and cleanup

- Mac and Pi complete package checks pass, including KAT request/response
  equality, KEM, ABI, canonical/failure, small-input and cleanup tests.
- 3841 dedicated cases pass on Mac ASan/UBSan and Pi: all eight input
  alignments, randomized and boundary-pattern messages, overlapping output
  before/at/after input, full surrounding-memory checks, and protected
  input/output end pages.

  selected on Mac. This does not claim execution on big-endian hardware.
- Instrumentation confirms ten permutations and one fully zeroed 200-byte

  to C's 39 clears / 27714 bytes, exactly two removed 336-byte scratch pairs.

### Reproduce

Keep A at baseline/, B at candidate/, and this package at candidate-c/ under
/home/pi/gt768-fused-shake-hashg-20260911-e41. Stage this experiment's
run_b_gate.py and test_fixed.c under experiment/, plus the same harness/
files used for B.

    python3 experiment/run_b_gate.py /home/pi/gt768-fused-shake-hashg-20260911-e41 --gate C --name c-gate-v1

Use a fresh name for another run. Exact inputs/flags and binary hashes are
in C-summary.json. Raw samples, logs, disassembly, binaries, KAT output and
commands are under .build/c-gate-v1 on Pi and .build/pi-c-gate-v1 locally.

The next register-resident D gate should use C as its baseline, since C has
already removed generic sponge and byte-reconstruction overhead. Promotion
would separately require synchronizing the actual SUPERCOP leaf and running
its package gate; that export has not been changed here.
