## Inverse packed-top producer/consumer

Main scratch coordinate in bytes:

`512*component + 256*half_s + 16*column + 8*top + 2*lane4`.

Each I16 load returns [alpha rows 4h..4h+3 | beta rows 4h..4h+3].
Total main scratch stays 1536 bytes; the existing 256-byte s8 tail is unchanged.
All I9 producer calls finish before any I16 consumer call.

I9 retains arithmetic through the 8h/4s transpose but removes the final eight
TRN .2d instructions. The low/high D halves already contain the four-row groups
the consumer needs, so it writes them directly to their packed-top destinations.
I16 changes each 2xLDR D + INS into LDR Q. The arithmetic/reduction and the
previous R^-1 terminal scale constants remain unchanged.

Static ledger (excludes C call setup / any future ABI wrapper):
- I9: 296 -> 304 instructions, 12 calls: +96.
- I16 main: 810 -> 778, 6 calls: -192.
- Net -96 instructions; no coefficient pass added; same scratch size.
- More fragmented producer stores could cancel the instruction saving.
  This is not an A76 cycle prediction.

The three source files are generated by generate.py only after contracts pass.
Model checks cover all 768 main coordinates and the producer half-store map.
The unchanged arithmetic inherits the previous M5E/scale evidence; this is not
a new independent whole-inverse symbolic range proof.

## ToBytes early consumer

Hold two transpose states (8 vectors plus ninth source each), not two w[9]
output arrays. For each public row, construct exactly one coefficient pair,
apply routing TBL, normalize, pack, and immediately write final bytes.
Earlier transpose values die as their last adjacent row consumes them.
SLI combines a>>8 and b<<4 without a separate shifted vector and ORR.

model.py interprets the candidate instructions, including TRN, TBL, BSL, INS,
SQRDMULH/MLS, SLI and ST3 lane. 67 input vectors (distinct tags, full-halfword
boundaries and random inputs) match the wire-map oracle exactly; each of 1296
bytes is written once. Backward liveness gives 23 vector values in the authored
order. Consecutive-register ST3 constraints and ABI handling are NOT solved by
that liveness count; no-spill remains unknown.
