# D3 VPMADDWD reduction gate

## Outcome

The exact signed-dword Montgomery reduction works. Under an optimistic memory
accounting, the complete direct-packed cubic BaseMul is **49 static
instructions per `Q16 x I3` tile larger** than the selected baseline. This is
a risk signal, not a cycle result: the two paths have different dependency
chains, execution-port pressure, and overlap opportunities. A namespaced tile
ASM and same-ELF paired machine benchmark are required to arbitrate it.

This conclusion compares complete paths:

```text
baseline: 18-route packed->plane P + current 11-chain cubic BaseMul
candidate: direct-packed pair routing + VPMADDWD/MR32 + diagonal products
           + exact coefficient-plane output
```

It does not compare MR32 alone against the 18-route P.

## Exact MR32 result

For `q=3457`, `qinv=12929`:

```text
q*qinv mod 2^16 = 1
t = int16(low16(S) * qinv)
u = (S - t*q) >> 16
```

is an exact Montgomery reduction with one `R^-1`, matching the existing
16-bit product. The AVX2 lowering is:

```text
vpmaddwd       form two signed products and add in dwords
vpmullw        form low-word t
vpmaddwd       [q,0] * t, producing t*q in dwords
vpsubd
vpsrad $16
```

For one canonical `[0,3456]` operand and one arbitrary signed-i16 operand:

```text
S                         [-226492416, 226485504]
S - t*q                   [-339767935, 339764480]
conservative postshift    [-5185, 5184]
```

Both dword operations are signed-32 safe and `vpackssdw` cannot saturate.
The compiled AVX2 oracle checks 200,000 lanes, including endpoint cases, and
also proves the `vpackssdw + vpermq 0xd8` order.

This caller contract covers Encap and the two Decap BaseMul sites. It does
**not** cover Keygen, where both operands are transform/baseinv results.

## Joint three-sum routing

The six target pair vectors per operand are searched together. Two new half
carriers `(S1,S2)` and `(S3,S4)` are shared by all of `s0`, `s1`, and `s2`.
Each target vector still draws from two different source halves and therefore
needs two lane-local selections and one merge:

```text
2 shared vperm2i128 + 6 * (2 vpshufb + 1 vpor) = 20 routes/operand
both operands                                      40 routes/tile
```

The generated byte masks are lane-simulated against every desired `(q,j)`
owner. This is both constructive and the lower bound within the selected
half-carrier / lane-local-shuffle model.

## Complete tile ledger

| Cost | Baseline | VPMADDWD candidate |
| --- | ---: | ---: |
| packed-to-plane P | 18 | 0 |
| joint pair-operand routes | 0 | 40 |
| ordinary variable Montgomery products | 9 | 3 |
| VPMADDWD data products | 0 | 6 |
| MR32 instructions | 0 | 24 |
| dword-to-word repack | 0 | 6 |
| fixed-zeta products | 2 | 2 |
| diagonal/output routing | 0 | 18 |
| spill / intermediate materialization | 0 | 0 |
| peak YMM | 16 | 15 |
| total static instructions | **83** | **132 optimistic** |

The official positive-zeta tile is parsed directly from pinned `basemul.s`:
65 instructions, of which 53 are arithmetic and 12 are loads/stores. Adding
the selected 18-route P gives 83.

The candidate arithmetic is 62 instructions: 15 for three packed diagonal
products (including three qinv premultiplies), 36 for the three exact pair
sums, eight for the two zeta products, and three final adds. It is already
`+9` versus the current arithmetic. Joint pair routing is another `+22`
after crediting the removed P, so the candidate is `+31` before the required
18-route extraction of the packed diagonal products is charged.

The candidate total deliberately reuses the baseline's 12 memory
instructions, ignoring any extra constant-operand pressure. It is therefore
an optimistic static count, but it is not a throughput or latency model.
In particular, replacing dependent `vpmullw/vpmulhw` Montgomery chains with
`vpmaddwd`, dword correction, and independent routing changes both critical
path and port occupancy. Only the linked machine object can decide cycles.

The final `c0/c1/c2` planes would be directly consumable by the existing
inverse entry, so no hidden post-output adapter is charged. The 18 output
routes are the exact P network needed to extract the three packed diagonal
products before the final cubic combinations.
