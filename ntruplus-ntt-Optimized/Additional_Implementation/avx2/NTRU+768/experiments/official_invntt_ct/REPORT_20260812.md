# Official NTRU+768 inverse CT experiment — 2026-08-12

## Outcome

This is a default-off experiment.  It does not change the production selector.
The frozen Official inverse remains the accepted implementation.

The experiment proves that the frozen Official terminal representation can be
permuted exactly into the existing F32X3 CT representation.  Its global
`R^-1` Basemul scale is absorbed into the CT terminal Montgomery constants, so
there is no separate scale pass in the measured endpoint.

The measured CT endpoint is not competitive:

| Endpoint | Median TSC | p10--p90 |
| --- | ---: | ---: |
| Official GS | 514--518 | 508--540 |
| layout adapter only | 312 | 308--334 |
| CT arithmetic only | 902--906 | 890--948 |
| Official boundary -> adapter -> CT | 1178--1184 | 1168--1236 |

Paired CT-arithmetic-minus-Official is +386 to +390 TSC.  Common-boundary CT
is +664 to +670 TSC.  Therefore even a hypothetical zero-cost layout adapter
does not make this CT realization faster than Official.

## Mathematical boundary

Input is the exact frozen `poly_basemul_scale` output:

- 12 Official physical quartic groups;
- coefficient-major vectors inside each group;
- signed lazy representatives with coefficient-dependent bounds;
- global Montgomery scale `R^-1`.

The public fixed adapter maps each Official `(record, partner, coefficient,
lane)` to F32X3 `(branch, row, j, coefficient)`.  The mapping was checked by 64
independent small-input Forward transforms against the scalar F32X3 Forward.
No per-slot multiplier was found: the relation is a pure permutation modulo q.

The CT transform uses five radix-2 CT layers, inverse DFT3, then the unchanged
outer CRT/trinomial reconstruction.  Yang's CT-in-both-directions result applies
to the radix-2 tower; the outer NTRU+ trinomial split is not itself a radix-2 CT
butterfly and was not reclassified as one.

## Scaling

The existing Y2 endpoint consumes `R^0`.  For this experiment every terminal
P/Q Montgomery constant is multiplied by `R` modulo q.  The linear CT/DFT3
network therefore retains the input `R^-1` scale until the terminal products,
which simultaneously perform untwist, inverse-length normalization, CRT
reconstruction, and `R^-1` compensation.

## Correctness

`make test` passes under ASan/UBSan with LeakSanitizer disabled because the
current Codex environment runs under ptrace:

- zero;
- 64 Forward representation comparisons;
- 1,000 deterministic Official Forward/Basemul products;
- modular equality against frozen `poly_invntt_scale`;
- 16 in-place alias cases;
- generated-terminal freshness check.

The CT output is canonical `[0,q-1]`; frozen Official commonly returns signed
representatives.  They are equal modulo q, but exact representative equality is
not claimed.  A production replacement would still require full KAT and the
downstream `poly_crepmod3` range/representative contract.

## Static evidence

The linked CT symbol is 4,413 bytes and has 929 static instructions.  The
adapter is 853 bytes and has 256 static instructions.  Frozen Official's exact
source span is 1,957 bytes; its prior selected-CFG ledger is 2,478 dynamically
executed instructions per inverse.

The CT endpoint pays for canonicalization throughout its five layers and for
192 qword terminal stores.  Official uses only 64 range-control chains and 48
contiguous YMM output stores.  These structural costs explain why CT-only is
already slower before charging the layout adapter.

## Decision

Stop this candidate at the experiment gate.  A future CT attempt is justified
only if it is generated directly in Official lane order and proves, before
assembly work, that it removes most per-layer canonicalization and ends with 48
YMM stores.  Merely fusing the 312-cycle adapter cannot recover the CT-only
386--390-cycle deficit.

## Follow-up: Official lane-native CT

The follow-up candidate satisfies the gate above.  It is generated from the
frozen Official GS source and table, stays in the Official physical lane
layout, and consumes the unmodified `poly_basemul_scale` terminal ABI.  For a
GS pair whose current lane scales are `s_a,s_b`, the generator emits the CT
twiddle `s_b/s_a` and propagates output scales `s_a,u*s_a`.  A single
register-resident correction at the radix-2/radix-3 boundary currently restores
the unchanged Official radix-3 and outer merge contract.

The five radix-2 CT layers contain no `vpmulhrsw` canonicalization sites.
Compared with Official, eight static radix-2 sites (four in physical level 6
and four in physical level 3), or 48 dynamically executed YMM
canonicalizations, are removed.  Twiddle Montgomery multiplications remain,
because they define the CT transform as well as reducing their operand.

The final level-0 loop is unchanged: six YMM stores per iteration for eight
iterations, exactly 48 YMM terminal stores.  There is no layout adapter and no
additional scratch materialization.

Correctness under ASan/UBSan:

- 1,000 arbitrary small terminal vectors;
- 1,000 Forward/Basemul products with inputs in `{-1,0,1}`;
- 1,000 Forward/Basemul products with inputs in `[-3,3]`;
- modular equality against frozen `poly_invntt_scale`.

Across these cases both implementations had the same observed maximum absolute
output representative, 1,855.  There were 143 coefficient representatives that
differed exactly by a multiple of q; no output-range expansion was observed.

The lane-native symbol is 2,085 bytes; frozen Official's source span is 1,957

## Canonical-table re-derivation

Re-derivation shows that the generated inner tables already have the canonical
twisted CT cardinality: physical levels 6 through 2 contain respectively
1, 2, 4, 8, and 16 distinct effective twiddles.  The remaining boundary
diagonal is not an arbitrary artifact of the GS-to-CT construction.  In each
of the six 32-point children it is one geometric sequence, shared by all four
quartic coefficient strands:

| child | successive boundary-scale ratio | ratio^32 mod q |
| ---: | ---: | ---: |
| 0 | 1100 | 867 |
| 1 | 1282 | 257 |
| 2 | 765 | 2333 |
| 3 | 1685 | 3091 |
| 4 | 361 | 1937 |
| 5 | 779 | 1886 |

Thus the boundary factor is exactly the root-coordinate restoration
`rho_j^-i` for each non-cyclic child `y^32-c_j`; none has `c_j=1`.

There is no table-only solution that makes these five CT layers directly equal
the plain Official radix-3 boundary while retaining the fixed Official lane
topology and pure CT butterflies `(a,b)->(a+t*b,a-t*b)`.  Each quartic strand
has an anchor terminal column that never passes through a CT twiddle, so every
choice of CT table gives 32 coefficients all equal to 1 for that column.
Frozen Official's corresponding column has 32 distinct coefficients in every
child.  Input/output permutation cannot turn a constant column into the six
required geometric columns.

This is reproducibly checked with:

```sh
make prove-canonical-ct
```

Consequently the mathematically complete canonical inverse consists of the
five inner CT layers plus this root restoration.  Removing the standalone
restoration requires fusing it into the parent radix-3 and level-0 maps (or
changing the Basemul terminal scale contract); twiddle-table reindexing alone
cannot remove it.

## Fused radix-3 root restoration

The standalone three-input correction has now been removed.  For every radix-3
triple the derived scales satisfy

```text
sY = sX*c
sZ = sX*c^2
```

so the generated radix-3 boundary computes `U=cY`, `V=c^2Z`, performs the
unchanged three-point arithmetic on `(X,U,V)`, and uses output multipliers
`sX`, `sX*alpha^-1`, and `sX*alpha^-2`.  The last two absorb the two existing
Official alpha multipliers.  The first output now also passes through a
Montgomery multiplication, eliminating Official's radix-3 `reduce2` Barrett
chain.  Arithmetic remains six modular multiplications per vector; there is no
separate untwist/correction pass.

The two radix-3 groups have identical `c,c^2` vectors.  The final schedule
therefore processes corresponding vectors from both groups together, keeping
the four `c/c^2` Montgomery constants live and reusing them.  This saves 32
dynamic YMM table reads versus processing the two groups independently.

Correctness remains unchanged under the full lane-native gate:

- 1,000 arbitrary terminal vectors;
- 2,000 Forward/Basemul products;
- ASan/UBSan;
- maximum observed output absolute value 1,855 for both candidate and Official.

Matched TSC after paired-group scheduling:

| --- | ---: | ---: | ---: |
| 1 | 504 | 508 | +4 (+0.79%) |
| 2 | 498 | 504 | +6 (+1.20%) |
| 3 | 496 | 500 | +4 (+0.81%) |
| 4 | 494 | 500 | +6 (+1.21%) |

The symbol is 2,213 bytes, 256 bytes larger than the frozen Official span.
The generated fused radix-3 table is 4,096 bytes; all generated CT tables
together are 10,240 bytes.  The radix-2 tower still has zero `vpmulhrsw`
canonicalization sites, and the unchanged final loop still executes exactly
48 YMM terminal stores.  This is now within 4--6 TSC cycles of Official but is
not yet a production promotion because of the code/table-size cost and the
remaining small regression.

## Reduction audit under the terminal range contract

The earlier zero-checkpoint CT result was correct for sampled reachable
Forward/Basemul products but not for the full documented terminal bounds.  A
new gate generates 10,000 deterministic terminal vectors independently within
the coefficient-specific `2q/3q/4q/4q` bounds.  With no checkpoint the first
failure appeared at vector 193; therefore that version must not be treated as
Official-ABI-compatible.

The minimal tested safe level-6 checkpoint reduces only the top and bottom
`c2,c3` paths.  The `c0,c1` paths remain lazy.  Removing any one of the four
retained paths caused a contract-range mismatch, whereas all 10,000 vectors,
the arbitrary-small tests, and 2,000 reachable products pass with all four.
This executes four YMM canonicalizations in each of six blocks, or 24 total.

Official executes 64 dynamic YMM Barrett canonicalizations: 24 at radix-2
level 6, 24 at radix-2 level 3, and 16 in radix 3.  The fused CT executes 24,
removing 40 of 64 (62.5%).  The remaining identity-twiddle Montgomery chains
are not algebraically necessary, but testing confirms that at least the first
level-5 identity chain is a necessary range checkpoint even with the selective
level-6 reductions.  They are therefore retained.

The stronger range gate changes the performance decision.  The ABI-safe CT
measures 518--528 TSC against Official's 494--504, a regression of roughly
22--24 cycles in the stable runs.  The 492-cycle no-checkpoint result is kept
only as evidence for a narrower reachable-input contract and is not eligible
for promotion under the frozen Official ABI.
