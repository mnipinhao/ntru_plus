# V3 Shared-Helper Slothy Result

Date: 2026-07-24

Machine: Raspberry Pi 5, Cortex-A76, core 3 pinned, Linux
`perf_event_open`. Both variants use the same Direct-CQ GT closure and
portable `NO_CE` SHAKE.

## Scope

The V3 pointwise function calls one shared helper for each of 24 QSoA groups.
The exact helper region contains 100 instructions excluding `ret`:

```text
2 loads
97 arithmetic / permutation / reduction instructions
1 store
```

This corrects the earlier 109-instruction description.

The candidate changes only the helper schedule and register allocation.
Gather offsets, group order, arithmetic, reductions, output layout, and the
outer V3 cross-group schedule remain unchanged.

## Register and Slothy contract

```text
v0       fixed reduction constants
v4-v7    current LHS group live-ins
v24-v31  next gather group, live-through and unchanged
v1-v23   helper allocation pool
x0/x2/x3 dst/RHS/zeta pointer streams
spills   forbidden
```

The upstream AArch64 model lacks the existing four-vector post-increment
`ld1`. The experiment driver adds that exact instruction form with consecutive
output-register constraints, N1 LSU assignment, throughput 2, and latency 5.
It does not split or replace the instruction.

Static gates:

```text
helper instructions                  100 -> 100
mnemonic multiset                    unchanged
q24-q31 instruction-region touches   0
spills                               0
Slothy self-check                    pass
kernel contract comparison           preserved
```

The N1 model reports 25 expected cycles before and after scheduling. It changes
the order but does not predict a cycle win.

## Interpretation

The V3 liveness-driven generator exposed all eight next-group loads. Slothy
then improved the helper itself by interleaving independent low/high widening
products and Montgomery/reduction chains. The Cortex-A76 gains about three
cycles per call even though the N1 model is flat, so measured A76 PMU is the
deciding evidence.

V3+Slothy was promoted to the production `pipeline` profile on 2026-07-24:

```text
asm/gt/decap/verify_pointwise_group_pipeline.S
```

The old source-order `compact` and fully unrolled `speed` profiles remain
selectable baselines. The clean release contains the same production body,
flattened without profile selectors or experiment symbols in
`asm/internal/decap_verify.S`.

Promotion gates:

The Pi 5 later returned to `kernel.perf_event_paranoid=2`, so an additional
isolated-binary PMU rerun could not be opened without interactive sudo. The
promotion therefore relies on the same-binary PMU above plus the exact
machine-code identity check; timer ticks were not substituted for CPU cycles.

## Macro and code-size note

A source macro can accept offsets such as `312` and `360` and emit the two
loads:

```asm
ldr d24, [x1, #312]
ldr d25, [x1, #360]
```

This improves readability and keeps the fixed map in one generator/macro
interface. The assembler expands every invocation, so it does not reduce
linked text size or dynamic instruction count. A runtime offset loop would be
a separate code-size tradeoff and would add address-generation work.
