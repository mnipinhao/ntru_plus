# Decapsulation Verify Group-Pipeline Result

Date: 2026-07-24

Machine: Raspberry Pi 5, Cortex-A76, core 3 pinned, Linux
`perf_event_open`. Both variants use the Direct-CQ GT production closure and
portable `NO_CE` SHAKE.

## Scope correction

The QSoA group sequence originally identified as `ntt.S` is not part of the
forward NTT. Its source is:

```text
asm/gt/decap/verify_pointwise_compact.S
```

The clean release flattens it into:

```text
asm/internal/decap_verify.S
```

The existing compact implementation already shares the 100-instruction
multiplication/reduction/store body through one helper. The repeated region is
the fixed-offset gather and transpose for 24 distinct QSoA groups.

## Transform

The candidate keeps all 620 dynamic instructions and all 24 helper calls.
For each transition from group N to group N+1, it moves five loads for the next
group before the current helper call:

```text
d24, d25, d26, d27, d31
```

Those registers are dead after the current transpose and are not referenced by
the helper. The remaining `d28-d30` loads stay after the call because the
helper clobbers those registers.

## V2 Wider Cross-Group Window

V2 remaps the helper-only temporaries:

```text
q28 -> q2
q29 -> q3
```

This makes `d28/d29` safe across the helper call. Seven next-group loads
(`d24-d29,d31`) move to the earliest point after each current value's last
transpose use. `d30` remains after the call because the helper still clobbers
`q30`.

## V3 Full Eight-Load Window

The helper originally holds three temporary `UZP2` results in `q30/q29/q28`.
V3 schedules those values through `q2/q3`:

```text
original q30 temporary -> q2
original q29 temporary -> q3
original q28 temporary -> q2 after the first q2 value's last use
```

This adds one local dependency to the helper but frees all of `q24-q31`.
Every next-group gather can therefore move before the current helper call.

## Runtime Offset Analysis

The gather map has pairwise regularity but is not globally affine. Examples:

```text
group 4 -> 5:   all eight offsets +24
group 20 -> 21: all eight offsets +24
group 0 -> 1:   mixed -24 and +24
other pairs:    include row-boundary wrap
```

Immediate-offset `ldr dN,[x1,#imm]` gives one dynamic instruction with a common
base and no inter-load address dependency. A runtime offset-table loop would
need an offset load and indexed data load, while pointer-update loops create a
serial address chain and still need exceptions for mixed/wrapped pairs.
Runtime offset generation may reduce static text but is not the preferred A76
speed path.

## Decision

Keep V3 as the best default-off compact candidate. The current paired compact
versus fully-unrolled F2 gap is 111 cycles. V3 recovers approximately 62-64
cycles relative to compact without increasing the static instruction count or
the 2,880-byte compact function.

Do not replace the immediate offsets with a runtime offset table: the offsets
are irregular, and the current immediate loads cost one instruction each.
Table-driven addressing would reduce static source repetition but add dynamic
address loads and dependencies.

Before production promotion:

1. run the full clean-release KEM/KAT gates;
2. decide whether the stable approximately 63-cycle full-decap gain justifies
   changing production source order.
