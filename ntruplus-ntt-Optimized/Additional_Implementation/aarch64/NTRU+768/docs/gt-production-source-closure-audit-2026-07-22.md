# GT production source-closure audit, 2026-07-22

This audit separates the selected full-KEM runtime from generic/reference
diagnostics without changing arithmetic, layouts, or protocol bytes.

## Interoperability

GT production and KPQC final generated byte-identical NTRU+768 KAT response
files:

```text
SHA256(PQCkemKAT_2336.rsp):
22c72039845361ff142273150a59785bada5146c04018ce0a8b67b99a647eaa8
```

An explicit cross-vector test then loaded the first `sk`, `ct`, and `ss` from
the KPQC final response file and called the GT production decoder:

```text
cross_vector_decap_rc=0
cross_vector_ss_mismatches=0
```

Therefore the selected GT production decapsulation accepts ciphertext emitted
by KPQC final. Internal NTT layouts and specialized kernels do not escape the
canonical key/ciphertext byte boundary.

## Removed full-KEM sources and symbols

The full-KEM source closure no longer links:

- `ntt.c`: C reference NTT, inverse NTT, baseinv, basemul, and basemul_add;
- `poly_gt_canonical.c`: portable canonical reference functions and the
  canonical-to-GT permutation table;
- `poly_canonical_pack_p1.S`: legacy generic keygen P1 pack;
- `poly_triple`: inactive with the selected fused BPQ keygen frontend.

The production pointwise assembly still needs `gt_rowbitrev_lambda`. Its
initializer is now shared by `ntt.c` and the minimal
`gt/rowbitrev_lambda.c`, so the 384-byte contract table remains without
pulling in the reference transform implementation.

The removed APIs remain available in `GT_PRODUCTION_GENERIC_SUPPORT_SOURCES`
and the generic/component profiler. Only the selected full-KEM binary uses
`GT_PRODUCTION_KEM_SUPPORT_SOURCES`.

`scripts/check_gt_production_binary_symbols.py` enforces both sides of the
closure: required specialized symbols must be present and known
reference/legacy symbols must be absent.

## Code size and cycles

Raspberry Pi 5 Cortex-A76, core 3 pinned, portable `NO_CE` SHAKE, 31 samples x
2000 calls, 100 warmups:

| Operation | Before text | After text | Text reduction | Before p50 cycles | After p50 cycles | Cycle delta |
|---|---:|---:|---:|---:|---:|---:|
| keygen | 144302 | 127798 | 16504 (11.44%) | 36367 | 36362 | -5 |
| encapsulation | 144286 | 127782 | 16504 (11.44%) | 37643 | 37575 | -68 |
| decapsulation | 144286 | 127782 | 16504 (11.44%) | 32859 | 32842 | -17 |

The primary result is the deterministic text reduction. The small cycle
changes include code-placement and instruction-cache effects and should not be
interpreted as isolated kernel speedups.

Post-closure comparison against KPQC final from the same run:

| Operation | KPQC final p50 | GT p50 | GT reduction |
|---|---:|---:|---:|
| keygen | 39962 | 36362 | 9.01% |
| encapsulation | 39059 | 37575 | 3.80% |
| decapsulation | 35193 | 32842 | 6.68% |
